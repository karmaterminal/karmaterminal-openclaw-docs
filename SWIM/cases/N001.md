# Case `N001` — Cross-session targeted continue_delegate return (`targetSessionKey`)

**Family**: Routes
**Lifecycle status**: new
**Evidence class needed**: live-row, cross-seat
**Provenance**: RFC §6.8 producer-IN/return-OUT contract; cohort substrate work 2026-04-28 (cross-session bridge); `swims/swim-42/rows/cross-session-targeted-return/`
**Registry version added**: v1

## Claim being proved

continue_delegate with `targetSessionKey` set delivers the return payload to the named recipient session, not to the originating session, and the recipient observes the payload as a real channel-feed event with the correct `traceparent` propagated.

## Required minimum row shape

From driver session, fire `continue_delegate(task, targetSessionKey=<recipient>)`. From recipient seat, capture the return payload as a `prompt.submitted` (or equivalent) channel-feed event. Verify the payload arrived at recipient AND not at driver. Verify `traceparent` continuity across the producer→queue→recipient hop.

## Evidence surface(s)

Recipient-side session jsonl trajectory showing the inbound event; driver-side absence of return payload; gateway journal for delivery routing; trace-tree query showing `continuation.delegate.dispatch` parent → `continuation.queue.deliver` child on the recipient side.
