# Case `N002` — Multi-recipient continue_delegate return (`targetSessionKeys`)

**Family**: Routes
**Lifecycle status**: new
**Evidence class needed**: live-row, cross-seat
**Provenance**: RFC §6.8 multi-recipient OUT contract; PR #551 multi-recipient targeting
**Registry version added**: v1

## Claim being proved

continue_delegate with `targetSessionKeys: [a, b, c]` delivers byte-identical text to all listed recipients, AND each recipient receives the same `traceparent`. Per-target FallbackResolver fail-isolation: if one recipient's delivery fails, the others still complete.

## Required minimum row shape

Fire delegate with multi-recipient targeting. From each recipient seat, capture the return payload. Verify payload bytes match across all recipients. Verify `traceparent` is identical across all recipients. Inject failure on one recipient and verify others still receive cleanly.

## Evidence surface(s)

Per-recipient session jsonl trajectory; byte-diff across recipient payloads (must be zero); trace-tree query confirming shared `traceparent`; failure-injection result vs healthy-recipient result.
