# Case `N006` — OTel trace-context (`traceparent`) propagation across queue boundary

**Family**: Observability
**Lifecycle status**: new
**Evidence class needed**: live-row
**Provenance**: RFC §6.7 / §6.8 OTel chain-correlation contract; `extensions/diagnostics-otel/src/continuation-tracer-adapter.ts`
**Registry version added**: v1

## Claim being proved

W3C `traceparent` carrier is accepted at the producer surface (continue_delegate tool param, bracket-token directive, PendingContinuationDelegate runtime field, TaskFlow PendingDelegateState durable field), persisted across the queue boundary, and re-applied by consuming spans so the resulting trace tree is connected end-to-end.

## Required minimum row shape

Fire continue_delegate with explicit `traceparent`. Verify carrier persisted on TaskFlow store. Verify recipient-side spans parent under the producer span via the carrier. Trace-tree query: `traceid:T AND name:continuation.delegate.dispatch AND children include continuation.queue.deliver`.

## Evidence surface(s)

Tool call with carrier; TaskFlow store query showing persisted `traceparent`; OTel span emission log; trace-tree query result confirming connected tree.
