# Case `N007` — OTel trace-context preserved through restart-replay path

**Family**: Recovery
**Lifecycle status**: new
**Evidence class needed**: live-row
**Provenance**: RFC §6.8 restart-resilience contract; `src/infra/session-delivery-queue-storage.ts`; `gateway/server-restart-sentinel.ts`; `post-compaction-delegate-dispatch.ts`
**Registry version added**: v1

## Claim being proved

Durable session-delivery queue persists `traceparent` per entry. After gateway restart, replay sinks re-apply the per-entry `traceparent` when re-delivering: queued `systemEvent` replay, queued agent-turn replay (both routed and unrouted), and post-compaction delegate replay. Recovery WITHOUT re-application produces orphaned successor spans (anti-claim must also be testable).

## Required minimum row shape

Stage queue entries with known `traceparent`. Restart gateway. Drain queue. Verify replayed entries re-apply the original `traceparent` via trace-tree query. Negative case: verify removing the re-application path produces orphaned spans (so the test catches degradation).

## Evidence surface(s)

Pre-restart queue snapshot; post-restart queue snapshot; trace-tree query over restart boundary; orphan-span detection (negative case).

- v1 (2026-05-06): added as `new` from RFC §6.8 restart-resilience contract
