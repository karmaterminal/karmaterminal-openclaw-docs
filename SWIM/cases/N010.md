# Case `N010` — Post-compaction successor receives correct state, not stale ghost state

**Family**: Recovery
**Lifecycle status**: new
**Evidence class needed**: live-row, cross-seat
**Provenance**: RFC §4.2 post-compaction lifecycle; cohort lesson on stale-ghost-state risk; `swims/swim-42/rows/post-compaction-lifecycle/`
**Registry version added**: v1

## Claim being proved

Post-compaction successor session receives the correct evacuated state from staged delegates AND does not receive stale ghost-state from pre-compaction context that should not have survived. Distinguishes between intended evacuation (delegates released into successor) and unintended bleed-through (pre-compaction context surfacing where it shouldn't).

## Required minimum row shape

Stage delegates with known evacuation payload. Trigger compaction. From successor session, verify delegates fire with correct payload. Cross-check: verify no pre-compaction context that should NOT have evacuated is present in successor (e.g. transient working state that should be summarized away, not carried).

## Evidence surface(s)

Pre-compaction TaskFlow snapshot of staged delegates; post-compaction successor session jsonl; positive evidence (intended state present); negative evidence (unintended state absent).
